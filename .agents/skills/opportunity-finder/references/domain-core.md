# Opportunity discovery core

Derived from the preserved Paul Graham source snapshot. These models are lenses, not market evidence.

## Retained models

- **Look for problems, not startup ideas.** Start with friction that exists without the proposed product.
- **Make something people want.** In discovery, translate this into finding behavior that signals importance; do not claim “want” before behavior or payment.
- **Iterative discovery.** An initial candidate is a direction for contact with reality, not an identity or fixed product thesis.
- **Do things that do not scale.** Manual observation and delivery can expose the real problem faster than software.
- **Founder/domain familiarity.** Prefer problems the user can see closely and users the user can reach.
- **Organic pull over presentation quality.** A few people taking costly action is stronger than many people liking a pitch.

## Candidate scorecard

Score each dimension `0` (absent), `1` (plausible), or `2` (observed):

| Dimension | Question |
| --- | --- |
| Recurrence | Does the problem repeat on a recognizable trigger? |
| Cost | Does it consume money, time, risk, delay, or lost revenue? |
| Workaround | Are people already doing something awkward instead of nothing? |
| Spend | Is money or paid labor already allocated to the result? |
| Access | Can the user reach five affected people quickly? |
| Familiarity | Can the user notice nuances outsiders miss? |
| Manual test | Can the result be attempted without a product build? |

The score prioritizes investigation; it does not validate a business. Reject candidates with no reachable evidence even if the theoretical market is large.

## Source limitations carried forward

The source framework is startup- and Silicon-Valley-centered, can overvalue founder intuition, and contains roleplay/style instructions irrelevant to this Harness. Counter these limits with explicit evidence labels, small local tests, and willingness to pursue service-scale opportunities.
